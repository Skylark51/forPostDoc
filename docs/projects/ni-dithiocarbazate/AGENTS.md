# Ni HTML 프로젝트 편집·계산·시트 지침

적용 범위: `docs/projects/ni-dithiocarbazate/`. 사용자 공통 지침 반영일: 2026-11-17 (KST).

## 편집 전 필수 확인

1. 현재 사용자 요청과 이 Ni 전용 AGENTS.md, 저장소 상위 지침을 읽고 편집 대상·승인 범위를 정한다.
2. 대상 HTML 및 git diff를 확인하여 다른 작업자의 변경과 현재 프로젝트 경계를 파악한다.
3. 시트 편집 시 정확한 문서·탭·행·열, 기존 수식·검증·그룹 배치·상태색을 먼저 읽는다.
4. 계산 편집 시 실제 wf/input.sh와 같은 종류의 기존 입력, 함수·용매·전하·다중도·자원·checkpoint 참조를 확인한다.
5. 파일명 정리 또는 실행 변경 시 충돌·의존 참조·실제 PID와 실행 중 파일, 사용자가 지정한 노드를 먼저 확인한다.
6. Ni 프로젝트 경로에만 변경을 적용하고, 변경 후 HTML 구조·표시 내용·diff를 검증한다. 이번 지침 반영 범위는 Ni HTML과 Ni AGENTS.md이다.

## 공통 준수 지침

### 1. 파일명

계산 input/output/chk는 날짜 없는 동일 stem으로 연결한다. 기존 날짜를 정리할 때 이름 충돌, %oldchk/%chk 및 후속 입력 참조, 실제 실행 PID와 열린 파일을 먼저 확인한다. 실행 중 파일은 보존하고, 안전한 정리 대상만 변경한다.

### 2. 노드 표기

B열은 라이온의 실제 노드 번호를 숫자로 기록한다. dumbo와 tachyon은 서버명을 그대로 기록한다. 두 서버는 scratch 번호 방식과 구분하며 임의 번호를 부여하지 않는다. 상태색은 기존 규칙에 따라 B열 노드 셀에 적용한다.

### 3. A열과 그룹

A열에는 실제 파일명 또는 하단 계산의 성격을 나타내는 간결한 제목을 기록한다. 그룹 제목은 bold로 표시한다. 운영 메모는 HTML 분석·복구 기록으로 옮긴다. “덤보 재검증”과 같은 운영 메모는 A열에서 제거한다.

### 4. freq와 bb

동일 구조의 freq/bb는 시트 한 행으로 관리한다. A열에는 freq 파일명, E열에는 해당 bb 결과를 기록한다. 실제 input/output은 기존 wf 흐름에 따른 별도 파일로 유지한다.

### 5. scan과 후속 경로

각 scan 위아래에 빈 행 한 개씩 확보하여 scan 사이 빈 행 두 개를 유지한다. TS → IRC forward/reverse → 각 IRC endpoint opt → freq → bb를 실제 wf 생성 순서와 참조로 연결한다.

### 6. 입력과 계산 조건

scan·하위 계산·기질 기준계는 실제 wf/input.sh 생성 양식을 따른다. Ni 프로젝트의 함수, basis, 용매, 전하·다중도, CPU·메모리, checkpoint 경로와 기존 계산 조건을 유지한다. NBO/stable 등 명시적으로 요청된 예외만 변경하며, 요청 범위를 벗어나는 ultrafinegrid 또는 route 옵션을 추가하지 않는다.

### 7. 기록과 보고

검증한 파일·출력·실행 상태에 근거해 관찰 결과, 해석, 다음 행동을 명료하게 기록한다. “~로 단정하지 않겠습니다”, “~라는 의미는 아닙니다” 형태의 부정재진술 대신 확인된 사실과 필요한 검증을 직접 쓴다.

### 8. 시트와 기록 위치

시트 추가·삭제는 사용자의 명시적 요청을 확인한 뒤 수행한다. Excel/Google Sheets에는 이해하기 쉬운 raw data를 기록하고, 분석·복구 이력과 판단 근거는 Ni HTML에 기록한다. 공용 시트·파일명 정리는 주 담당과 조정한다.

## 이번 반영의 작업 경계

이번 위임은 Ni HTML과 이 AGENTS.md의 지침 반영이다. 공용 Google Sheets, 계산 input/output/chk, 계산 재시작, 자동동기화, 다른 프로젝트 경로는 주 담당의 범위로 유지한다. 이후 작업은 해당 시점의 사용자 승인 범위와 위 사전 확인 절차를 따른다.
