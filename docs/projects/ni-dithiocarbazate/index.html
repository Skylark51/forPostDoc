공통 준수 지침

  1. 파일명 — 계산 input/output/chk는 날짜 없는 동일 stem으로 연결한다. 기존 날짜를 정리할 때 이름 충돌, %oldchk/%chk 및 후속 입력 참조, 실제 실행 PID와 열린 파일을 먼저 확인한다. 실행 중 파일은 보존하고, 안전한 정리 대상만 변경한다.
  2. 노드 표기 — B열은 라이온의 실제 노드 번호를 숫자로 기록한다. dumbo와 tachyon은 서버명을 그대로 기록한다. 두 서버는 scratch 번호 방식과 구분하며 임의 번호를 부여하지 않는다. 상태색은 기존 규칙에 따라 B열 노드 셀에 적용한다.
  3. A열과 그룹 — A열에는 실제 파일명 또는 하단 계산의 성격을 나타내는 간결한 제목을 기록한다. 그룹 제목은 bold로 표시한다. 운영 메모는 HTML 분석·복구 기록으로 옮긴다. “덤보 재검증”과 같은 운영 메모는 A열에서 제거한다.
  4. freq와 bb — 동일 구조의 freq/bb는 시트 한 행으로 관리한다. A열에는 freq 파일명, E열에는 해당 bb 결과를 기록한다. 실제 input/output은 기존 wf 흐름에 따른 별도 파일로 유지한다.
  5. scan과 후속 경로 — 각 scan 위아래에 빈 행 한 개씩 확보하여 scan 사이 빈 행 두 개를 유지한다. TS → IRC forward/reverse → 각 IRC endpoint opt → freq → bb를 실제 wf 생성 순서와 참조로 연결한다.

  7. 기록과 보고 — 검증한 파일·출력·실행 상태에 근거해 관찰 결과, 해석, 다음 행동을 명료하게 기록한다. “~로 단정하지 않겠습니다”, “~라는 의미는 아닙니다” 형태의 부정재진술 대신 확인된 사실과 필요한 검증을 직접 쓴다.
