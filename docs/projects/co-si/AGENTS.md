# 작업 폴더 규칙

- 사용자가 명시적으로 요청하지 않는 한 새 하위 폴더를 만들지 않는다. 로컬의 새 계산 입력·계획·검증 자료는 이 작업 폴더 최상위에 파일로 저장한다.
- 라이온의 새 Co–Si 계산 입력과 산출물은 기존 `/home/skylark/EightSNU/AfterPhD`에 직접 배치한다. 계산별 디렉터리나 분석용 하위 디렉터리를 만들지 않는다. scratch는 기존 `/scratch/skylark`를 사용한다.
- 이미 있는 폴더나 원본 계산 결과를 임의로 삭제·이동하지 않는다.
- 계산 준비와 계산 실행을 구분한다. 준비 요청만 있을 때는 입력·의존성·실행 방법을 마련하고 실행 상태를 미실행으로 명시한다.
- 라이온 실행 시 사용자가 지정한 우선 노드 `28 29 30 38 39 40 48 49 50 51 34 44 21 25`에서 유휴 상태를 먼저 확인한다. 기존 `wf`와 `/home/skylark/script/input/input.sh`의 실행·입력 방식을 따르고 Gaussian 옵션을 임의로 추가하지 않는다. Co–Si의 이번 계산 용매는 CPCM benzene이다.

## 편집 전 필수 확인

- 작업 전에 이 파일과 Co–Si HTML의 공통 지침을 읽고, 대상 파일·시트·계산 단계와 사용자 요청 범위를 확인한다. 공유 `forPostDoc` 저장소에서는 Co–Si 프로젝트 경로만 수정한다.
- 입력·출력·체크포인트의 실제 파일명, 상하위 참조, 실행 중인 프로세스와 충돌 가능성을 확인한다. 기존 날짜 제거는 연결된 `%chk`·`%oldchk`, 실행 스크립트, HTML·엑셀 참조까지 검토한 뒤 적용한다. 실행 중인 파일은 보호한다.
- 기존 시트 목록, A/B/E열의 값·수식·서식, scan 주변 빈 행과 wf 의존성을 확인한다. 수정 후 변경 범위와 참조·행 배치를 검증한다.
- 실제 `wf`·`input.sh` 템플릿과 기존 Co–Si 계산의 함수·기저함수·용매·분산·전하·다중도·자원을 대조한다. 준비·실행·완료는 출력과 프로세스 근거로 구분하여 기록한다.

## 계산 파일·엑셀·HTML 공통 지침

1. 새 계산의 input/output/chk 파일명에는 날짜를 붙이지 않는다. 기존 날짜 파일의 이름 변경에는 위 사전 확인을 적용한다.
2. dumbo/tachyon 계산의 B열에는 각각 `dumbo` 또는 `tachyon`을 적는다. 두 서버는 서버명으로 관리하고 임의 scratch 번호를 붙이지 않는다.
3. A열은 실제 파일명 또는 하단 계산의 성격을 나타내는 간결한 제목으로 작성한다. 그룹 제목은 **bold**로 표시하고, '덤보 재검증' 같은 운영 메모는 제거한다.
4. 동일 구조의 freq/bb는 한 행으로 관리한다. A열에는 freq 파일명을, E열에는 bb 결과를 기록한다.
5. scan 행 위아래에 빈 행을 한 행씩 확보하여 scan과 scan 사이에는 빈 행 두 개를 유지한다. TS → IRC → IRC endpoint opt-freq-bb는 실제 wf 흐름과 의존성에 맞게 연결한다.
6. scan·하위 계산·기질 기준계 입력은 실제 `wf`·`input.sh` 생성 방식을 그대로 따른다. NBO/stable 등 사용자가 명시한 예외 외에는 요청하지 않은 ultrafinegrid 추가나 route 변경을 하지 않는다. 기존 Co–Si 함수·기저함수·CPCM benzene·계산 조건을 유지한다.
7. 보고·지침은 확인된 사실과 남은 검증을 명료하게 쓴다. 부정 재진술이나 불필요한 운영 문구를 피한다.
8. 시트 추가·삭제는 사용자가 명시적으로 요청한 경우에만 수행한다. Excel/Google Sheets에는 이해하기 쉬운 raw data를, HTML에는 분석·복구 기록을 담는다.

지침 문서·HTML 반영 요청의 작업 범위는 해당 문서 편집이다. 계산 재시작·새 계산 실행·시트 생성은 각각 해당 사용자 요청에 따라 수행한다.
