# BODIPY 계산·시트·HTML 작업 지침

적용일: 2026-11-17 KST. 범위: 11.KAIST의 BODIPY 자료와 forPostDoc/docs/projects/bodipy/. 사용자가 승인한 작업 범위를 먼저 따른다.

## 편집 전 필수 확인

1. 현재 사용자 요청, 이 AGENTS.md, BODIPY HTML의 작업 지침을 읽고 편집 대상과 승인 범위를 확인한다.
2. 기존 Excel/Google Sheets의 A/B/E열, 그룹 제목, scan 주변 빈 행, TS/IRC/endpoint 순서와 실제 원자료를 읽는다. 대상 셀·행과 보존할 수식·서식을 먼저 특정한다.
3. 해당 기질·계산 종류의 실제 wf, input.sh, 원본 input 및 output route를 대조한다. 함수·기저함수·용매·전하·다중도·자원·checkpoint 경로·부모 계산 연결을 확인한다. 다른 프로젝트의 경로나 조건을 BODIPY에 이식하지 않는다.
4. 파일명 변경 전 대상 파일과 참조하는 input·스크립트·시트·HTML을 확인하고, 이름 충돌과 실행 중 프로세스·checkpoint 사용 여부를 점검한다. 실행 중 파일은 보호한다.
5. Git 상태와 최신 원격 변경을 확인한다. 공유 저장소에서는 BODIPY 프로젝트 경로만 편집·스테이징한다. 변경 후 파일명·참조·행 배치·데이터·조건을 대조하고 HTML에 근거와 확인 시각을 기록한다.

## 공통 지침

1. 계산 input/output/chk 파일명에 날짜를 붙이지 않는다. 기존 날짜 제거는 충돌·참조·실행 중 파일 보호 확인을 마친 뒤 승인 범위 안에서 수행한다.
2. dumbo/tachyon은 서버명 자체로 관리한다. B열에는 실제 서버명 dumbo 또는 tachyon을 기록한다. 임의 번호를 만들지 않는다. 다른 서버는 해당 프로젝트의 검증된 표기 규칙을 유지한다.
3. A열에는 실제 파일명 또는 하단 계산의 성격을 나타내는 간결한 제목을 쓴다. 그룹 제목은 bold로 표시한다. '덤보 재검증' 같은 운영 메모는 HTML에 기록한다.
4. 동일 구조의 freq/bb는 한 행에 정리한다. A열에는 freq 파일명, E열에는 bb 결과를 기록한다. 계산 파일의 분리 실행 방식은 기존 wf를 유지한다.
5. scan 행의 위아래에 빈 행을 한 행씩 확보해 scan과 scan 사이에는 두 행 간격을 유지한다. TS, 양방향 IRC, IRC endpoint opt-freq-bb는 실제 wf 흐름과 부모·자식 계산 관계에 맞춰 연결한다.
6. scan 및 하위 계산, 기질 기준계는 실제 wf/input.sh 생성 방식을 그대로 따른다. 프로젝트별 함수·기저함수·용매·기존 계산 조건을 유지한다. NBO/stable 등 명시적으로 요청된 예외만 적용하며, ultrafinegrid·tight·route 옵션을 임의로 추가하거나 변경하지 않는다.
7. 보고와 지침은 확인 사실, 수치, 근거 파일, 확인 시각, 다음 행동을 명료하게 쓴다. '~로 단정하지 않겠습니다', '~라는 의미는 아닙니다' 같은 부정재진술 대신 현재 확인 결과와 남은 확인 사항을 직접 쓴다.
8. 시트 추가·삭제는 사용자의 명시적 요청이 있을 때만 수행한다. Excel/Google Sheets에는 이해하기 쉬운 raw data를, HTML에는 분석·검증·복구 기록을 둔다.

## 현재 승인과 재생성

이번 승인은 지침 문서와 BODIPY HTML 반영이다. 계산 재시작·새 계산 제출·파일명 일괄 변경·시트 추가/삭제는 별도 사용자 요청 범위에서 수행한다.

BODIPY 대시보드를 재생성할 때 workflow-guidelines.html과 작업 지침 링크를 유지한다. 과거 audit의 권고를 옮길 때 이 지침과 대조하며, 기존 tight/ultrafine 자동 권고를 다시 넣지 않는다. 계산 확인 시각과 지침 적용일은 각각 기록한다.
