계산·파일명·시트 편집 지침

적용: V·Ni와 forPostDoc HTML 하위 연구 프로젝트 · 사용자 지시 2026-11-17

모든 편집 작업 전에 확인

① 이 지침과 프로젝트별 원본 시트·wf/input.sh·입력 템플릿을 읽는다. ② 대상 파일·시트·범위·계산 상태·수식·서식을 확인한다. ③ python edit_preflight.py --action "이번 편집 내용"으로 확인 기록을 남긴다. ④ 지침에 맞게 편집한다. ⑤ 파일 참조·셀·수식·서식·행 배치를 다시 읽고 결과를 검증한다. 자동 동기화와 후속 작업에도 같은 절차를 적용한다.

  1. 파일명: 모든 계산 input·output·chk와 후속 파생 파일 이름에서 20261116 같은 날짜를 제거한다. 계산 시점은 output 기록을 사용한다. 이름 충돌은 구조·경로·branch 등 계산의 차이를 표현하여 구분하고 원본을 보존한다. %chk·%oldchk·등록표·자동화·HTML·시트 참조를 함께 갱신한다. 실행 중인 파일은 작업 상태와 참조를 확인하여 계산 연속성을 유지한다.
  2. B열: Lion은 실제 배정 노드 번호를 사용한다. dumbo와 tachyon은 각각 dumbo, tachyon으로 입력한다. 두 서버에는 scratch 노드 번호를 붙이지 않는다. 상태색은 기존 B열 규칙을 따른다.
  3. A열: 실제 파일명 또는 하단 계산들의 성격을 나타내는 간결한 제목을 적는다. 그룹 제목은 bold로 표시한다. 운영 시점·복구 작업명은 HTML에 기록한다.
  4. freq와 bb: 동일 구조는 freq 파일명을 A열의 대표 이름으로 사용한다. D열에는 작은 basis SCF, E열에는 대응 bb SCF를 기록한다. freq와 bb 결과는 같은 행에 모은다. 실제 input/output은 wf/input.sh의 단계별 파일 구조를 유지한다. 단원자처럼 진동수 계산이 적용되지 않는 기준계는 실제 작은 basis 파일명을 사용한다.
  5. scan 배치: scan 행 위아래에 각각 한 행을 확보한다. 이웃한 scan과 scan 사이에는 두 행의 간격을 둔다. 후속 결과는 wf 순서에 따라 TS·양방향 IRC·IRC 끝점 opt/freq/bb로 연결한다. 검증된 TS를 중심으로 reverse/forward 끝점을 기존 시트 방향에 맞춰 위아래에 배치한다.
  6. 입력 생성: scan과 모든 하위 계산은 실제 wf 및 input.sh 생성 방식을 따른다. 함수·basis·용매·분산·전하·다중도·CPU·메모리·checkpoint와 route는 해당 프로젝트 원본 조건을 따른다. NBO·stable 등 목적이 명시된 특별 계산은 예외를 기록한다. 요청하지 않은 ultrafinegrid, 적분격자, 수렴 옵션 등은 임의로 추가하지 않는다. 기존 완료 output은 실제 계산 조건의 원자료로 보존하고 조건 차이는 HTML에 기록한다.
  7. 기질·소분자 기준계: 같은 입력 생성·파일명·freq/bb·시트 배치 원칙을 적용한다. 계산 조건을 일치시켜 반응 경로와 기준계의 연속성을 유지한다.
  8. 시트 권한과 내용: 시트의 추가·삭제는 사용자의 명시적 요청에 한하여 수행한다. Excel/Google Sheets에는 이해하기 쉬운 raw data를 기존 주제별 시트에 모은다. 분석·복구 이력·준비도 평가·운영 보고는 HTML에 보관한다. 이번 정리에서는 야간복구의 고유 파일명·자료를 앞쪽 기존 시트에 이관하고, 두 야간 시트의 전체 기록을 HTML에 보관한 후 해당 두 시트를 삭제한다.
  9. 문체: 사실에 근거한 명료하고 단정적인 어조를 사용한다. 근거에서 해석으로 이어질 때는 “~으로 나타나므로, ~라고 여겨집니다”와 같이 작성한다. “~로 단정하지 않겠습니다”, “~라는 의미는 아닙니다” 같은 부정재진술은 금지한다.
  10. 하위 프로젝트: Mn-peroxo·Co–Si·V–Oxo/Peroxo·Ni·BODIPY에 이 공통 지침을 적용한다. 프로젝트별 원본 계산 조건과 기존 시트 양식을 함께 확인한다.
